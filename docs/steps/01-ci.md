# Step 01 — CI: GitHub Actions

**Roadmap row:** 1 · **Branch:** improve/01-ci · **PR:** n/a (merged directly) · **Merge commit:** pending

## What changed
Added `.github/workflows/ci.yml` running, on every push to `main` and every pull request:
`pytest -q tests/`, `bash -n install.sh`, `shellcheck -S warning install.sh`, and
`python -m py_compile` over every tracked `*.py` plus `dictate` and `hotkeyd/hotkey-relay`
when present. Added the CI badge to `README.md`. Files touched: `.github/workflows/ci.yml`
(new), `README.md`, `docs/steps/01-ci.md` (new).

## Why
Roadmap row 1: every later step needs a safety net independent of whoever claims the step is
done. It is also the precondition for merging the two feature branches, whose combined tree
nobody has ever run as a unit.

## How it was verified
- cloud: `python3 -m pytest -q tests/` → `37 passed`; `bash -n install.sh` → clean;
  `shellcheck -S warning install.sh` → exit 0 (9 info-level findings printed, not gating).
- pop-os: n/a.

## Deviations from the roadmap row
- Lint gated at `warning`, not shellcheck's default: at the default the v1.0 tree already
  fails on 9 info-level findings (SC2012 x3, SC2015 x6). All findings are still printed.
- The compile step discovers files via `git ls-files` rather than the literal
  `polish.py dictate`, so it keeps covering new entry points as they land.

## How to revert
`git revert -m 1 <merge-sha>`. No on-machine step; nothing outside the repo changes.
